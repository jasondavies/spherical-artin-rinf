# Lean 4 / Mathlib formalisation of the R∞ criterion for exceptional spherical Artin groups

This directory formalises the argument of `../paper/main.tex` in Lean 4 with Mathlib. It covers:

* the Reidemeister-number lemmas (Lemma 2.1);
* the abstract criterion: Theorem 3.1, Lemma 2.11, Corollary 2.9 and Remark 3.2, including the
  F4 swap variant;
* the Artin group as a presented group, the homomorphism `f : A → ℤ^T ⋊ Perm T` (Lemma 2.4), and
  `P^ab` as a permutation module (Proposition 2.6, apart from the cited rank statement);
* the finite certificates for **all six types H3, F4, H4, E6, E7 and E8**, checked by the Lean
  kernel with `decide +kernel`;
* for **H3 and F4**, also the computation of `Out(W/Z(W))` (part of Proposition 4.1(b)), by
  enumeration.

The cited deep inputs are **explicit hypotheses** of the final theorems. They are not global
`axiom`s, so each theorem's type shows what it depends on.

Toolchain: `leanprover/lean4:v4.35.0`, Mathlib `v4.35.0`. These are the same pins as in the user's
other projects.

## Build

```
cd lean
lake exe cache get          # Mathlib oleans (fast if ~/.cache/mathlib is populated)
LEAN_NUM_THREADS=4 lake build
```

Measured build time, from a clean `.lake/build` with the Mathlib oleans already present: **10 min 46 s
wall clock, 31 min CPU** (`LEAN_NUM_THREADS=4`, on a shared 16-core machine, 2026-11-07). The
slowest modules are:

* `Types/F4Out` (7.4 min): `Out` verification for F4;
* `Data/E8` and `Data/F4Out` (about 3 min each, mostly writing `.ilean` files for the large tree
  literals);
* `Types/E7` (3 min), `Types/H4` (2.5 min) and the three `Types/E8/Orb*` modules (2.7 min each, in
  parallel).

Peak memory: individual Lean processes reached about 25 GB RSS (observed for `Types/E7` and
`Types/H4`), so the build needs a machine with ample RAM.

After `lake build`, `lake env lean scripts/print_axioms.lean` prints the axioms and statements.

There is **no `sorry`**, **no `native_decide`** and **no `axiom`** anywhere in `ArtinRinf/`.
All finite computations use `decide +kernel`, so they are evaluated by the Lean kernel. The trusted
base is therefore the kernel only, not the compiler. The `#print axioms` output is below.
`decide +kernel` adds no axiom.

## Main theorems

For `X ∈ {H3, F4, H4, E6, E7, E8}` the file `ArtinRinf/Types/X.lean` contains:

```lean
theorem ArtinRinf.X.artin_X_R_infty
    (hW   : Finite M.Group)                               -- W(X) is finite
    (hCP  : (pure M).Characteristic)                      -- Cohen–Paris
    (hBr  : Nonempty (Abelianization (pure M) ≃* Multiplicative (Fin N → ℤ)))  -- Brieskorn
    (hOut : OutGeneratedBy D.ρ.range π₀) :                -- Out(W/Z) is generated by π₀
    ∀ φ : ArtinGroup M ≃* ArtinGroup M, reidemeisterAut φ = ⊤
```

* `M = CoxeterMatrix.X` is **Mathlib's** Coxeter matrix.
* `ArtinGroup M` is the presented group `⟨S | Π(s,t;m) = Π(t,s;m)⟩`.
* `M.Group` is Mathlib's Coxeter group.
* `pure M = ker (ArtinGroup M → M.Group)`.
* `N` is the number of reflections: 15, 24, 60, 36, 63, 120.
* `reidemeisterAut φ : ℕ∞` is the number of `φ`-twisted conjugacy classes, with `⊤` meaning
  infinitely many.
* For H3, F4 and H4, `π₀` is the explicit outer permutation. For E6, E7 and E8, `π₀ = 1`, so
  `hOut` says that every automorphism of `W/Z` is inner.

| type | main theorem | outer case | hypotheses |
|---|---|---|---|
| H3 | `ArtinRinf.H3.artin_H3_R_infty'` | stable | **only `hW`, `hCP`, `hBr`** (`hOut` proved in `Types/H3Out.lean`) |
| F4 | `ArtinRinf.F4.artin_F4_R_infty'` | **swap** (`π₀` exchanges `U_long`, `U_short`) | **only `hW`, `hCP`, `hBr`** (`hOut` proved in `Types/F4Out.lean`) |
| H4 | `ArtinRinf.H4.artin_H4_R_infty` | stable | `hW`, `hCP`, `hBr`, `hOut` |
| E6 | `ArtinRinf.E6.artin_E6_R_infty` | all inner | `hW`, `hCP`, `hBr`, `hOut` |
| E7 | `ArtinRinf.E7.artin_E7_R_infty` | all inner | `hW`, `hCP`, `hBr`, `hOut` |
| E8 | `ArtinRinf.E8.artin_E8_R_infty` | all inner | `hW`, `hCP`, `hBr`, `hOut` |

For H3 and F4, the unprimed versions `artin_H3_R_infty` and `artin_F4_R_infty`, which also take
`hOut`, remain available.

How the abstract criterion is phrased:

* **Good constituent.** It is encoded as `CommScalar ρ U`: every `ℚ`-matrix commuting with all
  `ρ(a)` acts on `U` as a scalar. This is exactly what the proof uses.
* **Swap case.** The paper uses `U₁ ∩ U₂ = 0` only to see that `u = v + M v ≠ 0`. The Lean witness
  instead checks `hπv ≠ ±v` directly on the explicit witness vector.
* **The permutation `π`.** It is not assumed separately for each `φ`. It is produced from `hOut`.
  `hOut` is a statement purely about the finite permutation group `ρ(W) ≤ Perm T`: every
  automorphism of `ρ(W)` is conjugation by some `g ∈ ρ(W)` or by some `g π₀`.

## Hypotheses standing for cited or computed results

| Hypothesis | Meaning | Source | Status in Lean |
|---|---|---|---|
| `hW : Finite M.Group` | the Coxeter group is finite | classical (Coxeter) | Hypothesis. Used only to get `[A:P] < ∞`. |
| `hCP : (pure M).Characteristic` | `P = ker(A→W)` is characteristic | Cohen–Paris 2003, Thm 1.4. Computer-assisted (GAP). | Hypothesis. |
| `hBr : Nonempty (P^ab ≃* ℤ^N)`, with `N` the number of reflections | `H₁(P;ℤ)` is free abelian of rank `N` | Brieskorn (`P = π₁` of the complement), plus `H₁` of an arrangement complement (Orlik–Terao) | Hypothesis. The *equivariant* identification is then **proved** (`permModuleIso`). |
| `hOut : OutGeneratedBy D.ρ.range π₀` | automorphisms of `W/Z(W) ≅ ρ(W)` are inner, or inner times `π₀` | `code/indep/out_check.py` and `fastaut.py`. For E8: paper Prop. 4.2, by hand. | **Proved for H3 and F4.** Hypothesis for H4, E6, E7 and E8. |

`D.ρ` is the permutation representation built from the exported generator permutations. So `hOut`
concerns exactly the permutation group that `code/indep/out_check.py` enumerates: it is generated
by the same permutations, computed by the same `rootsys.py`.

`hBr` does not mention the exported data, only the number of reflections. `hW` and `hCP` are
statements about Mathlib's Coxeter group and our `ArtinGroup` alone.

## Trust in the finite data

`scripts/export_data.py` and `scripts/export_out.py` export the data into `ArtinRinf/Data/*.lean`:

* the generator permutations;
* orbital labels with a BFS spanning forest;
* integer bases of the constituents;
* `π₀`;
* witness words and vectors;
* for H3 and F4, an enumeration of `ρ(W)`, its involutions, relation tables and conjugators.

The scripts read `../code/indep/rootsys.py` and `indep_check.explicit_pi0`. They write nothing in
`code/` and set `dont_write_bytecode`. They are **untrusted**: every property used is re-checked by
`decide +kernel`, so wrong data would make the build fail.

The tables of the large cases (E8 and F4-Out) are stored as balanced binary trees (`BT.lean`). This
gives the kernel logarithmic lookups.

`scripts/gen_types.py` generates `Types/{H4,E6,E7,E8}.lean` from a template.
`scripts/split_e8.py` then splits the E8 certificate checks into `Types/E8/*.lean`, so that they
are checked in parallel. `Types/H3.lean`, `Types/F4.lean`, `Types/H3Out.lean` and
`Types/F4Out.lean` are hand-written.

Checked per type by `decide +kernel`:

* the generators are involutions that fix their own reflection;
* the braid relations hold in `ℤ^T ⋊ Perm T` (Lemma 2.4);
* the Coxeter relations hold in `(ℤ/2)^T ⋊ Perm T`;
* every reflection is conjugate to a simple one (explicit words);
* the orbital certificate: every label class lies in one orbit, via a BFS forest;
* every orbital matrix maps every basis vector of `U` to a fixed multiple of itself;
* the witness vectors;
* `π₀` is an involution normalising `ρ(W)`.

The Out-verification (H3, F4) additionally checks:

* the 60 (resp. 576) listed permutations are closed under the generators and all lie in `ρ(W)`;
* every involution is listed;
* every tuple of involutions whose pairwise products have the right orders is conjugate to the
  generators by the tabulated element of `ρ(W) ∪ ρ(W)π₀`. There are 120 such tuples for H3 and
  1152 for F4, i.e. `|Aut| = 2|ρ(W)|`.

## Remaining gaps

* `hW`, `hCP` and `hBr` are not formalised. They are classical or cited theorems; Cohen–Paris is
  itself computer-assisted.
* `hOut` is not formalised for H4, E6, E7 and E8. The groups have orders 7200, 51840, 1451520 and
  348364800, which is too large for kernel enumeration. For E8, the paper's hand proof
  (Prop. 4.2 + Lemma 3.5) is not formalised.
* Lemma 2.12(ii), the character certificate, is not formalised. The commutant certificate (i) is
  used instead, as in `certify.py`.
* Section 6 (inversion; centre-fixing automorphisms), Section 5 (A_n, B_n, D_n) and the dihedral
  discussion are not formalised.
* The identification of `T = Fin N` with the set of reflections of `W` is not formalised. The logic
  does not need it: the theorem is about the genuine `ArtinGroup M`, and `T` enters only through
  `hBr` (the rank) and `hOut` (see above).
